## Interfaces and decisions

- `004_participation.sql`: public RPCs `save_session`, `publish_session`,
  `cast_session_vote`, `join_session`, `withdraw_participation`,
  `get_session_snapshot`; named inputs suffixed `_input`, plus `request_id`.
  Mutations return JSON results and structured database error messages.
- All mutations validate current active membership. Session-row locks serialize
  allocation, withdrawal and publication. Server clock is sampled **after** lock
  acquisition. Confirmed players plus live held offers consume capacity; existing
  waiting/offered players prevent a later requester bypassing the queue.
- Private actor/request UUID ledger: same request/payload returns original result;
  conflicting payload/operation reuse fails. Reservation and mutation are atomic.
- Draft create/edit then publish with one open participation poll. Published
  session details cannot be rewritten in this phase. Admins may vote as members.
- Vote choices are English **Play / Not playing**. Same affirmative vote preserves
  priority; explicit rejoin gets a fresh timestamp. Append-only audit retains old
  timestamps/states. A separate liability floor retains a prior 75% late-cancel
  liability even if that player rejoins the waiting list.
- KL calendar-day withdrawal percentage comes from a private pure SQL helper;
  public operations always supply server time. No self-withdraw after start.
- Normal RLS reads list sessions. Detail snapshot includes authoritative server
  time, own state/actions, counts and Task 2's safe roster projection.
- UI extends the existing green/off-white Manrope system. Member home lists
  upcoming/history sessions; detail shows vote/join/withdraw, roster and fee state.
  Admin list/editor supports real draft save/edit/publish. No fictitious stats.

## Review focus

Last-slot contention, delayed row-lock acquisition crossing a time boundary,
duplicate and conflicting request IDs, rejoin behind a pre-existing queue,
published-time tampering, stale membership, retained late-cancel liability,
no other player's private data and no client-supplied identity/time/percentage.
