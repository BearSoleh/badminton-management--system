## Scope and interfaces

Create the Section 5 core schema in `002_core_tables.sql`, permissions and a
private receipt bucket in `003_permissions.sql`. Tables provide the foundation
for Tasks 3–8; participation, billing mutations, payment review, guest capability
exchange and admin UI remain in their respective phases. All client writes to
those domain tables fail closed, including writes by an admin JWT.

Use `get_session_roster(session_id_input uuid)` as an explicit safe projection:
session/participant ID, display name, participation and attendance only. It checks
current database membership and session visibility; underlying identities remain
private. Suspended members retain own obligation reads, never join privileges.

Use `authorize_receipt_view(object_path_input text)` to authorize an existing
receipt path. The `receipt-view` Edge Function verifies the bearer with Auth,
calls that RPC as the caller, then issues a **60-second** URL with a server-only
client. No authenticated Storage SELECT policy exists, so clients cannot mint
arbitrarily long links. Uploads are insert-only and tied to an eligible own charge;
path format: `<user UUID>/<charge UUID>/<object UUID>.(jpg|jpeg|png|pdf)`.
Guest requests are denied until the scoped backend transport in Task 7 exists.

## Review focus

1. A guessed foreign charge/path must never become an upload or view entitlement.
2. Suspended admin/member JWTs must lose privileges without needing a new JWT.
3. Draft/cross-session records cannot leak via safe roster or relational joins.
4. Tokens/outbox and private audit details must never be public/client mutable.
5. Financial history cannot cascade away when a user/session is deleted.

## Limits

60-second links are bearer capabilities until expiry; logout/suspension cannot
revoke an already issued URL. No real receipt files or external services in tests.
MIME/size upload restrictions are a foundation; content verification and payment
submission/approval, guest reservation concurrency and billing rules are later
tasks. Do not claim these later behaviors implemented by schema constraints.
