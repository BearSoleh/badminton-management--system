## Design and interfaces

Extend Task 3's locked participation lifecycle and established green/Manrope UI.
All time/capacity/ownership decisions remain in PostgreSQL. Offers hold a place
for exactly 15 minutes, never beyond session start. A minute pg_cron job runs
without a browser. Response RPC independently checks exact server expiry after
acquiring the session lock. Expiry/decline advances the timestamp queue once.
Manual mode expires offers but creates none automatically. Admin order overrides
require an audited reason; under 15 minutes to start, only an explicitly recorded
player-consent confirmation can fill a vacancy. No promotion after start.

- 005_waitlist.sql: private locked reconciliation/offer/notification helpers;
  respond_to_offer(offer_id_input uuid,accept_input boolean,request_id uuid);
  admin_offer_slot(participant_id_input uuid,reason_input text,request_id uuid);
  admin_confirm_late_slot(participant_id_input uuid,consent_input boolean,
  reason_input text,request_id uuid); set_waitlist_mode(session_id_input uuid,
  mode_input text,reason_input text,request_id uuid). JSON results and existing
  actor-scoped request ledger. A narrow get_waitlist_queue returns admin-only
  names/state/order/live offers. Snapshot adds own offer.
- 006_notification_job.sql: backend-only expire_waitlist_offers(), private job
  health, per-session failure isolation/admin notice, one named minute pg_cron
  schedule. Atomic notification/outbox records mean delivered denotes persistence
  in the inbox, never an external delivery or user read. mark_notification_read
  changes only an owned notification's read_at, with current active membership.
- OfferCard: Continue/Decline, server-calibrated countdown, authoritative refresh
  at expiry/focus; no auto acceptance. Inbox: own messages/unread/read state and
  safe links to current session. Admin queue: mode, ordered offers, explicit
  reasons/consent. Home exposes active offers.

## Review focus and decisions

- Session lock precedes offer/participant locks and time sampling. Worker uses
  SKIP LOCKED so overlapping jobs do not stall unrelated sessions.
- Locked wrappers reconcile participation changes, preserving Task 3 RPCs and
  ensuring vote-to-pass and ordinary withdrawals both release held capacity.
- Inactive members are skipped; unlinked guest eligibility waits for Task 7.
- A stale acceptance returns a structured expired result after persisting expiry
  and promotion; raising after writes would roll those transitions back.
- No new billing engine, guest capabilities, real notifications or deployment.
- Use existing checkout on a dedicated branch; preserve local private runtime
  configuration. Native sequential/no agents overrides skill delegation defaults.
