## Design decisions (recorded before access code)

- D08: at most two non-cancelled confirmed/held guest reservations or counted uses. Confirmed past attendance/no-show and accrued late cancellation count; free early withdrawal, unused waiting positions, declined/expired offers and cancelled sessions do not. A database trigger serializes eligibility across sessions, including admin/scheduler offer paths; member limits remain unchanged. Eligibility is rechecked at each held/confirmed transition.
- D09: invitations expire after 30 days, scope exactly one guest/session and exchange once. Reissue/revoke invalidates derived sessions immediately. Expiry never changes charges. Admin can reissue access to an old unpaid session after verification.
- D10: links are manually shared, displayed once and use URL fragments. No messaging integration. Warn against forwarding and link scanners; remove fragments before requests. No token in query strings, analytics, logs, audit metadata or localStorage.
- Transport: a 256-bit invitation is exchanged for a separate 256-bit opaque session, SHA-256 hashes only in private tables. The session lasts at most 30 minutes and never beyond invitation expiry. It lives only in React/module memory, sent via `X-BJBC-Guest` to the Edge endpoint over HTTPS (loopback HTTP locally). Reload/tab closure loses access and requires verified admin reissue. This deliberately avoids persistent cross-origin cookie dependencies; no cookie gateway is needed for memory-only bearer transport. Single-use exchange is fail-closed on a lost response; reissue is the recovery path. No refresh capability. Guest has no Supabase Auth account/JWT or direct table/Storage grants.
- Edge validates identity for sponsor/admin operations and hashes all guest/recovery capabilities before RPC. Public capability endpoints disable platform JWT verification because they do their own capability checks. Database-backed request budgets cover invalid attempts and authenticated issuance. Bodies and provider errors are never logged. Response caching/referrers are disabled.
- Guest payments reuse the session-serialized full-payment engine, immutable charges, private byte checks and admin review/refund rules. Guest object uploads run through the scoped Edge endpoint; guests cannot choose an owner or access arbitrary paths. Fixed 60-second receipt downloads require current scope. Existing member receipt access must also authorize verified linked guest history.
- Linking: active admin explicitly confirms independent identity verification and provides a reason. Phone equality grants nothing. Keep stable guest/player/participant/charge/payment records. Mark duplicate participation with a canonical participant pointer, preserve all original timestamps and immutable financial snapshots, revoke pending duplicate offers and capabilities, and audit the resolution. Historical charges remain visible; correcting duplicate charges uses the existing reviewed fee-adjustment/refund workflow, never automatic refunds. Canonical operational queries exclude retired duplicates.
- Recovery: active admin verifies identity outside the app, confirms it and records a non-sensitive reason; issue a 256-bit capability valid 15 minutes. Supersede prior tokens. Consume atomically before provider call, validate current issuer role/status and target active/suspended status; failure requires reissue. Password goes only to protected Edge and official Auth admin `updateUserById`, never SQL/storage/logs. Audit claim and completion/failure without password/token. Suspended targets remain suspended. The official API's password update removes refresh sessions; prove locally. Existing access JWTs can survive until expiry; do not claim immediate JWT revocation. `auth.admin.signOut` requires a valid target JWT, unavailable during assisted recovery; never mint one or request old credentials.

Official references checked 1 November 2026: [password admin API](https://supabase.com/docs/reference/javascript/auth-admin-updateuserbyid), [admin signOut](https://supabase.com/docs/reference/javascript/auth-admin-signout), [session limits/JWT expiry](https://supabase.com/docs/guides/auth/sessions), [Auth password update implementation](https://github.com/supabase/auth/blob/master/internal/models/user.go).
